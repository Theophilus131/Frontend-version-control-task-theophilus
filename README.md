
# Frontend Version Control Task - Theophilus

## Purpose
This repository was created to demonstrate my understanding of Git and GitHub workflows, including repository setup, branching, committing, pull requests, merging, reverting commits, and branch renaming.

## Branches and Purpose
- `main` - stable branch containing merged project updates
- `feature-header` - created to build and style the page header
- `feature-footer` - created to build and style the page footer
- `feature-bottom-section` - renamed version of `feature-footer`

## Lessons Learned
- Branches help developers work on features independently without affecting the main codebase.
- Pull requests make collaboration and code review easier.
- Good commit messages improve project history and communication.
- Git revert is a safe way to undo mistakes while preserving history.
- Merge conflicts happen when the same lines are changed differently, and they must be resolved manually.
